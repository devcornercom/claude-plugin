# Changelog

The devcorner plugin for Claude Code. A new version comes with a release of devcorner, tagged `plugin-vX.Y.Z`.

## 0.28.0 — 2026-10-29

- A subagent that waits on its own background work is not taken for stopped (dc-t576). A worker that runs a long check in the background, as `pnpm check:heavy --sign`, ends its turn to wait for it, and Claude Code resumes it when the check ends; its `SubagentStop` made devcorner end its session and offer its run again, so a second worker started a second check beside the first. The hook now tells devcorner how many background tasks the subagent started itself still run, a number it counts on this machine from Claude Code's list of tasks in flight and the subagent's own transcript, neither of which leaves it; while that is more than none, devcorner leaves the session and its run alone. An older plugin, which cannot tell, has its worker's run end as before, and the worker takes it back when it resumes.
- The plugin says when delivery is off, and signs a new machine in itself (dc-t576, part 4). Signing in with `/mcp` gives the agent devcorner's tools only; the hooks, the wake and the line above the prompt need this machine's hook token, and with none the hook script exits without a word, so a window looked connected and heard nothing. Now, with no token, each session's start says in the transcript `devcorner: delivery is off in this window: this machine has no hook token, so devcorner's messages, dispatches and wakes never reach this conversation, though the agent's devcorner tools still work.`, with how to turn it on (`/dc login`, asking Claude, or `DEVCORNER_TOKEN`), and `/dc` says the same. On the plugin's first run on a machine with no token, it begins `/dc login` itself, once: the line above the prompt shows the code to approve and the transcript says where; `/dc logout` stops it, and later starts only say how. A cloud session, which is never signed in, a machine with `DEVCORNER_TOKEN`, and a plain `-p` run are told nothing. `pnpm check:heavy --sign` in devcorner's repo now signs with the token `/dc login` saved when `DEVCORNER_TOKEN` is not set, so one sign-in serves both.

## 0.26.0 — 2026-10-29

- The line above the prompt stays one short line in a terminal that draws no links (dc-t577). In macOS Terminal, and wherever else Claude Code does not draw links, each linked part of the line was drawn as its words followed by its whole address, so the line ran long and wrapped. The plugin now asks the environment what Claude Code asks it (`FORCE_HYPERLINK`, the terminal's name and version, tmux, colour and the rest of Claude Code's rule), since the plugin API does not say: where Claude Code draws links the parts stay linked, and elsewhere the line says the same words with no address, `devcorner · s7 reviewer · waiting 2`. The sign-in line says its address there once, whole, with the code filled in, which a terminal that draws no links still opens from its text, as macOS Terminal does. The desktop and other surfaces, which draw a link as an anchor, keep the links whatever the terminal. `FORCE_HYPERLINK=1` turns the links on, as it does for Claude Code.

## 0.24.0 — 2026-10-27

- The line above the prompt is one line of links, with nothing to press (dc-t533): `devcorner · s7 reviewer · waiting 2`. "devcorner" opens the project's home (else the workspace's place, or Personal's for a repo in none), `s7`, the short id of the session this conversation works as, opens that session's page, the conversation's name follows it as its label, and `waiting 2` opens the project's inbox, said only while something waits there ("2+" or "?" while a part of devcorner could not be read). With no session there is no id and no label. On a narrow terminal the label is cut at a word, else left out; nothing else is cut. Every button is gone: `[ now ]`, more and less, `[ + N more ]` and `[ fewer ]`, `[ copy ]` and `[ open ]`, `[ message ]`, Sign in and Cancel, Set it up and Not now. What the open row said, `/dc` says as text: the project's picture, the session's ticket, the paste to copy, your other live sessions, what waits by work stream, the OA, what is moving, cloud sessions, Next, the code, and a relays' pause, each with its page. `/dc now`, `/dc waits`, `/dc sessions`, `/dc paste` and `/dc send` are as they were. `/dc more` and `/dc less` are gone, so those words ask devcorner as any others do, and the row's reads ask devcorner for nothing more than the line.
  - Signed out, the line says `devcorner · not signed in · /dc login, or ask Claude to sign it in`; while a code shows, `/dc logout` stops the sign-in, as Cancel did.
  - In a repo devcorner does not know, the line says `devcorner · new project here · /dc setup sets it up · /dc hide hides this`. `/dc setup` asks Claude, as your own words, to set the repo up, as Set it up did; `/dc hide` stops the offer for the repo, remembered as Not now was. devcorner has no page that adds a repo to a workspace, so these stay commands.
  - A paste an agent of this conversation writes is said in the transcript as `devcorner: paste me-p14 "Reply to the reviewer" is ready for you to copy: /dc paste copies it, or press Copy on <its page>`.
